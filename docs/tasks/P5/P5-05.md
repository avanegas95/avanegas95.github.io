## Behaviour / rules
1. Workflow triggers: `pull_request` (any base) and `push` to `feat/blob`; `permissions: contents: read`; no secrets referenced; no deploy job. Never edit `deploy.yml`.
2. Bundle check re-scoped: budget (25 KB gzip) applies to the JS graph reachable from the `<blob-agent>` entry module only (identify it by the `src/scripts/blob/index` chunk, not by "all scripts on `/`"); React island chunks are excluded from the budget. **Every** client chunk is still scanned for the forbidden strings (secret names, `upstash`, `sk-ant-`, prompt slice). Until P5-04a lands, the check passes with "no Blob entry found" only if no `blob-agent` appears in any HTML (fail closed once it does).
3. Lighthouse: `/`, `/orbithop/`, `/privacy/`, `/blog/` (drop `/quality/`); ≥ 0.95 every category, results to `reports/lhci/` (gitignored), uploaded as an artifact only. If v1 pages fail today, record the baseline scores in the report and open a follow-up; do not lower thresholds.
4. Legacy E2E against the static build: `/orbithop/`, `/privacy/`, `/app-ads.txt` → 200 with expected content; `/Anderson_Vanegas_Resume.pdf` is never a PDF from the build (static) and the `vercel.json` rule is a 302 to LinkedIn (unit).
5. `csp.spec`: no CSP violations on `/` and `/blog/` when served with `vercel.json` headers applied by the test server (reuse v3's approach).
6. `/api/chat` is intercepted in every E2E; a test fails if any request reaches `api.anthropic.com`.

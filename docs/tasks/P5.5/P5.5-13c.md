# P5.5-13c: Voice lock, `facts:check` and site-drift ratchet (O13c)
Role: test-engineer · Model: sonnet · Reviewer: opus · Depends on: P5.5-13a, **H3 (Anderson confirms the locked-field set)**

> **Voice rule (all P5.5 tasks):**
> - Never write, paraphrase, shorten, "fix" or reorder Anderson's prose.
> - This task builds the guard that enforces the rule, and must not touch any prose itself.

## Goal
CI fails when any Anderson-owned prose field changes without his acceptance, and when a section component hard-codes a fact that belongs in the KB. A report-only `facts:check` lists conflicts and never writes.

## Files you own

## Interfaces
- `voice-lock.ts`:
  - `hashFields(kbRoot): Record<"<file>#<fieldPath>", string>` (sha256 of the NFC-normalised value)
  - `diffLock(lock, current): {changed[], added[], removed[]}`
  - CLI modes: `check` (exit 1 on any diff), `init` (refuses if the lock exists), and `accept` (see rule 2)
- `facts-check.ts`: `runChecks(kb, siteSources): Finding[]`, where `Finding = {rule, file, line, message, severity: "error"|"suggestion"}`. The CLI prints the findings and exits 0, or exits 1 on an `error`.

## Behaviour / rules
1. Locked fields are `VOICE_FIELDS` as confirmed at H3. The default is every KB body, `summary`, `headline`, `lede`, role `bullets`/`note`, and project bodies.
2. `accept` is for Anderson only:
   - It refuses when `!process.stdin.isTTY` or `CI` is set.
   - It shows each changed field old → new.
   - It marks whether the new value appears verbatim (whitespace-normalised) in `docs/content-intake/site-copy.md`.
   - It requires typing `accept`.
3. Agents may run `init` once in this task: it only snapshots the current, already-approved text.
4. `facts:check` never writes files. It reports:
   - DISCREPANCIES interim-rule breaches (D-03: a year count like `\d+\+? years`; D-05: `Boston, MA` without "area"; D-09: `TestRails`; D-14 per its row);
   - date and title mismatches between KB and site;
   - PII via `pii.ts`;
   - a small known-misspelling list, as `suggestion` only.
5. `site-drift`:
   - For each section component, fail if it contains a fact pattern: year ranges, `years of experience`, job titles (`SQA Engineer`), or employer names from the KB.
   - Exception: lines listed in that component's allow file.
   - Also fail if an allow-file line no longer matches, so the ratchet only shrinks.
   - Seed each allow file with the current hits.
6. No section, KB or CLAUDE.md edits. Put the proposed CLAUDE.md voice-rule text in the report for the orchestrator.
